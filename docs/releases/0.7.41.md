# DSCODE 0.7.41

DSCODE's terminal now ships as one self-contained application package per Mac architecture, with a private runtime and separate user data.

## Self-contained installation

Each archive includes pinned Node 24.21.0, Harness, the compiled TUI, plugins and native modules. The installer and first launch no longer need Node, npm, pnpm, a Hub profile or runtime downloads. Runtime patches are applied while building a clean staging tree. External project tools, Chrome and model credentials remain user-configured.

## Coexistence with existing DSH

DSCODE supplies its own Harness home and private runtime, discards inherited DSH runtime configuration and Node injection options, and installs only the `dscode` command. Sessions, credentials, configuration and terminal UI preferences live outside the package. Generated defaults form a separate base bundle so startup preserves native user overrides across upgrades and relocation. Existing DSH configuration and old DSCODE credentials are not imported automatically; the distribution guide documents explicit migration.

## Whole-package upgrades

The updater checks the release digest, platform, version and bundled modules before replacing the application. Failed checks preserve the old version and failed swaps restore it. User data is never moved into the update staging tree. Kernel locks protect running sessions; successful updates keep the previous package. The default update does not downgrade and there is no npm fallback. Power-failure transactional recovery is not promised.

The build also generates a Homebrew formula consuming the same archives. Adoption by the external tap is a separate publication step; the current tap must not be assumed migrated. Desktop remains a separate extension distribution.
