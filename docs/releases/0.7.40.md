# DSCODE 0.7.40

Credential-scoped balance snapshots, fresh status queries and clearer ACP failures.

- **Cached balance identity:** footer and Desktop balances clear immediately when credentials change or are removed. Late responses from an obsolete request cannot restore the old reading, including during credential resolution or response-body parsing. Refreshes resolve the native credential service when it becomes available after plugin startup. Transient failures retain a previous reading only for the same credential and source; authentication refusal clears it. Billing fixtures cover these transitions without real credentials or paid inference.
- **Currency and source:** cached amounts retain the reported currency and identify account funds versus a fallback key spending limit. CNY is displayed as CNY, malformed amounts remain unknown, and a valid zero remains zero. The public numeric balance API remains compatible; Desktop adds currency and source metadata. This does not change provider billing or currency conversion.
- **Fresh `/status`:** the TUI and ACP expose the selected provider and model plus a fresh DeepSeek or OpenRouter balance query, independently of the footer cache. Account funds and key limits remain distinct, credentials are not printed, and unsupported providers, unavailable data, timeouts and request failures have explicit states. The command does not send a model request or change the selected model.
- **ACP model choices and failures:** the picker lists providers with configured credentials or account login, plus saved custom services that require no authentication, while retaining the current model. Reconnect after credential changes to refresh the picker; local configuration does not prove endpoint reachability or model access. Failed prompts send a labeled notice before the failed response, with bounded transport details and retry guidance. Cancellation and successful completion keep their existing semantics.
- **Markdown guidance:** model instructions explain delimiters for code containing backticks and literal backslashes, and concise labels for long file links. They do not rewrite generated code or guarantee valid Markdown in every response.

Update the launcher with `npm install -g @toddzheng024/dscode@latest`, then run `dscode update` for an existing Hub profile. For official Harness Desktop 0.2.0-rc.2 on macOS Apple Silicon, install `@toddzheng024/dscode-desktop@0.7.40`, enable it, then fully quit and reopen Desktop.

Verification of the code passed `npm run check`: lint, both TypeScript gates, 1,129 unit/component tests, native integration, package checks and 63 offline evaluations, with 80.55% first-party `.mjs` coverage. PR CI passed on Node 22 and Node 24, plus Linux e2e. An independent Harness 0.2.0-rc.2 native Host passed packed Desktop usage checks across generation, resume and unload, including temporary native credential updates, removal, obsolete responses, currency metadata and key-limit fallback. Billing and model responses in these probes are synthetic. Public release installation is checked after publication and recorded in issue #16. Real billing, paid model inference, signed Desktop GUI interaction and real mail delivery have no automated case in this change.
