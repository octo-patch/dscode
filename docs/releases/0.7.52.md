# DSCODE 0.7.52

DSCODE adds direct Anthropic API-key support, restores pasted-image markers, and updates the shipped Computer Use bundle for Harness rc.3.

## Anthropic provider

Use `/login anthropic` or `ANTHROPIC_API_KEY`, then `/provider anthropic` and `/model`. The built-in catalog includes Claude Opus 5.5, Sonnet 5.5 and Fable 5.1, each with a 1,000,000-token context window and a 128,000-token maximum output budget. Opus defaults to medium effort; Sonnet and Fable default to high. Account access, quotas and billing remain controlled by Anthropic. This is API-key access, not Claude subscription login or automatic model discovery.

The provider supports images, streamed text, tool calls and adaptive thinking. It preserves the original content order and signed thinking across unchanged request prefixes. A changed model, key, system prompt, tool set or conversation prefix invalidates the bound thinking while retaining text and tool calls. Incomplete streams fail without committing a partial assistant turn. Empty tool-argument deltas no longer erase an initial empty input object. The existing token-throughput display uses the provider's reported usage.

Anthropic defaults to compaction at 50% of the usable input window: reserving 128,000 output tokens leaves 872,000 input tokens, so the trigger is 436,000. Background summary prefetch starts at 348,800, and completed summaries apply at safe step boundaries while preserving the later conversation tail. Explicit threshold settings take precedence; pruning can avoid a summary when it brings usage below the trigger. See the [Anthropic guide](../anthropic.md).

## Compatibility and pasted images

The shipped Computer Use bundle moves to 0.3.6, which declares compatibility with Harness `0.2.1-rc.3`. Build and standalone preflight checks reject incompatible profile bundles, and standalone qualification rejects skipped-bundle warnings. No version exemption is granted. The separate Desktop runtime remains on its existing Harness version.

Bracketed image pastes now remove the entire terminal wrapper before detecting attachment paths. Previously, the closing wrapper could leave an invisible ESC byte, making a valid PNG path appear as ordinary text. `[Image 1]`, subsequent image numbers and attachment delivery are restored, including quoted paths with spaces and paste blocks split across reads. Command-V still depends on the terminal supplying an image path; macOS Ctrl-V reads the clipboard image directly. Unbracketed character-by-character input remains ordinary typing.

## Validation

Before release preparation, the installed local package passed a real PTY image-paste reproduction after failing the same case before the fix. Fifteen focused input, paste and layout checks, lint, both TypeScript checks and documentation checks passed. The macOS clipboard helper passed its private-pasteboard self-test without changing the user's clipboard.

Live Sonnet and Opus checks each passed four coding/resume turns and five compaction checkpoints, including full-window synchronous and asynchronous compaction. Each retained all 40 checked facts; asynchronous checks preserved all 94 later messages and reused the prefetched summary without a second summary request. These are bounded acceptance runs, not a production success-rate guarantee. The extended compaction fixtures used an 8,192-token summary cap and disabled retries; ordinary settings retain their own budgets and retry policy.

Release qualification runs the full lint, type, coverage, integration, package and evaluation gate, then verifies the exact standalone archives on macOS ARM64, Intel macOS, Linux x64 and Linux ARM64 before publication. Native Command-V behavior in every terminal, Fable extended-chain inference, and native OS permission dialogs are not covered by these automated cases. Desktop has its separate package qualification and publication path.
